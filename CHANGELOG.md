# Changelog

All notable changes to SentinelAI are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
While the version is 0.x, minor releases may contain breaking changes.

## [Unreleased]

### Added

- Project documents: `CHANGELOG.md`, `SECURITY.md`, `CONTRIBUTING.md` and the
  plugin author guide `docs/PLUGINS.md`.
- README: "Getting started in 5 minutes", "Daily digest", "Deployment" and
  "Hardening and limits" sections, and terminal screenshots (SVG) generated by
  `scripts/make_screenshots.py`.
- **Alert-to-incident correlation** (`correlation` package). After a scan,
  alerts that share an IP or user (optionally host) within a time-gap window are
  grouped into an incident with a kill-chain-ordered timeline; repeated alerts of
  the same rule and entities collapse into one entry with a count. Incident score
  is the highest alert score plus 5 per extra distinct kill-chain stage (at most
  +20, at most 100). A lone alert is not an incident. Incidents are advisory:
  they never change alert scores or automated response.
- `sentinel incidents [--limit --ip --user --min-level --json]` and
  `sentinel incident <id> [--graph --json --triage]`. `--triage` is an advisory
  LLM verdict stored on the incident (needs `ai.llm.enabled`).
- Incidents in reports: a scan-summary line, an `incidents` array (plus
  `incidents_total` and `incidents_by_level` in `summary`) in the JSON report,
  and an "Incidents" section in the HTML report with the timeline and the
  Mermaid graph source in a collapsed block (no external scripts are loaded).
- `correlation` config section: `enabled`, `window_seconds`, `link_by`,
  `min_alerts`, `stage_bonus`, `max_bonus`, `max_timeline`.
- Benchmark: scenarios `incident_ssh_chain` (brute force, root login, privilege
  escalation, cron persistence must form exactly one incident) and
  `incident_benign_admin_session` (no incident), and the optional
  `labels.yaml` keys `expect.incidents`, `expect.incident_rules` and
  `expect.incident_stages`.
- Known limitations: linking by user can merge unrelated activity of a shared
  account such as `root` within the window; re-scanning the same log stores the
  incident again, like alerts; incident summaries are English only.
- **Sigma rule import** (`sigma` package, off by default). Loads a safe, minimal
  subset of Sigma rules from a directory and runs them as extra detection rules
  with ids `SIGMA-<first 8 hex of the Sigma UUID>`. Not a full Sigma engine, no
  pySigma. Supported: Linux logsources (services `auth`, `secure`, `sudo`, `su`,
  `sshd`, `cron`, `syslog`, `messages`, `daemon`, `kern`, `docker`, `nginx`,
  `apache`, `fail2ban`, `ufw`; categories `process_creation`, `webserver`,
  `firewall`), selections and keyword lists, modifiers `contains`, `startswith`,
  `endswith`, `all`, `cidr`, `exists`, `*`/`?` wildcards, and the condition
  grammar `and`/`or`/`not`/parentheses/`1 of`/`all of`. Everything else (`re`
  and other modifiers, aggregations, `timeframe`, `N of` with N other than 1,
  fields without a SentinelAI equivalent, non-Linux logsources, auditd,
  journald) is reported as unsupported with a reason, never approximated.
- `sentinel rules import <dir> [--json] [--max-rules N]`: dry run that lists
  importable and unsupported rules and prints the config snippet. `sentinel
  rules` also lists loaded Sigma rules when `sigma.enabled` is true.
- `sigma` config section: `enabled`, `rules_dir`, `max_rules`, `max_file_kb`
  (environment: `SENTINELAI_SIGMA_*`). Sigma ids are accepted in
  `detection.suppressions`, `detection.enabled_rules`/`disabled_rules` and
  `risk.rule_weights`; `sentinel tune` does not tune Sigma rules.
- Licensing: SigmaHQ rules are not bundled (Detection Rule License 1.1). Every
  Sigma alert carries the rule author, a license notice and the first reference
  in its description and context.
- `sentinel eval --sigma-rules <dir>` scores Sigma rules in the benchmark.
  `examples/sigma/` (original rules, MIT) and a separate frozen benchmark root
  `benchmarks/sigma/` with an attack and a benign look-alike scenario per rule.
- Known limitation: Sigma rules evaluate only the first 8192 characters of each
  event field.

## [0.1.0] - 2026-11-04

First tagged state of the project. It summarises everything that exists.

### Added

- **Detection engine** with 22 built-in rules (R001-R060) plus the `AI001`
  behavioral anomaly, each tagged with MITRE ATT&CK techniques. Rules are
  registered with `@register_rule`; sliding-window state is shared through the
  rule context.
- **Parsers** for syslog/auth, Apache access and error, Nginx access and error,
  Docker daemon, Fail2Ban and UFW logs, auto-detected from content, streaming
  (including gzip) with malformed lines skipped, never fatal.
- **Risk scoring**: a 0-100 score per alert with a per-factor explanation.
- **AI engine**: Isolation Forest anomaly detection (optional `[ai]` extra),
  behavior profiling and multi-stage attack-pattern recognition.
- **Threat intelligence** (AbuseIPDB, VirusTotal, AlienVault OTX) with disk
  cache, rate limits and a per-run lookup budget.
- **Structured local-LLM triage** for `sentinel explain`: the model must answer
  with a schema-validated JSON verdict; the verdict is advisory only and never
  changes risk scores, alerts or responses. Log text is treated as untrusted
  (sanitised, delimited, grounding check on cited events), with a deterministic
  template fallback and an injection corpus under `benchmarks/injection/`.
- **Evaluation harness**: `sentinel eval` runs a frozen, hash-verified benchmark
  of labeled scenarios (per-rule precision/recall, false positives per 1k
  benign events, MITRE coverage) and acts as a CI regression gate against
  `benchmarks/baseline.json`. `--triage` measures the configured LLM separately.
- **Human-approved tuning loop**: `sentinel feedback`, `review` and `tune`
  turn analyst labels into bounded proposals (thresholds, time-boxed
  suppressions, risk weights) that are checked against the frozen benchmark and
  applied only with `--apply`, to a machine-managed overlay with history and
  rollback.
- **Safe automated response** (off by default, `dry_run` adapter by default):
  self-lockout protection (admin ranges, SSH peer, default gateway, own
  addresses), approval mode, an append-only audit log with rotation, hourly
  circuit breaker, TTL reaper for temporary blocks, and `sentinel respond` for
  pending/approve/deny/reap/rollback/history. Reference UFW adapter in
  `examples/firewall_adapter_ufw.py`.
- **Onboarding**: `sentinel init` generates a validated `config.yaml` for the
  host (never prompts, automatic blocking stays off); `sentinel doctor` checks
  the environment and exits 1 only when a check failed.
- **Daily digest**: `sentinel digest` summarises recent alerts in plain language
  (en, tr, de) and, with `--send`, delivers it via Telegram, Slack or email.
  Secrets come from `SENTINELAI_NOTIFY_*` environment variables.
- **Packaging**: a non-root `Dockerfile`, systemd units for `sentinel live` and
  a daily digest timer under `deploy/`, and an environment-file template.
- **Hardening**: input limits (`limits.max_line_chars`,
  `limits.max_decompressed_mb`), ReDoS review of the parser and classifier
  regexes (bounded input windows), hypothesis-based fuzz tests for the parsers,
  and offline intel mode (`intel.offline`) that answers from the local cache
  only.
- **Plugin system**: `*.py` files in `~/.sentinelai/plugins/` (or
  `$SENTINELAI_PLUGINS_DIR`) can register rules, parsers, anomaly models and
  report renderers. See `examples/plugins/example_rule.py`.
- **Reports** in JSON, CSV and self-contained HTML; live monitoring with
  rotation-aware tailing; historical replay; event search.
- CI: ruff, mypy, pytest and the benchmark regression gate on Python 3.10-3.13,
  plus a Docker image build and smoke test.

### Fixed

Found by the benchmark and by review:

- R051 (Firewall Modification) no longer flags plain `ufw allow`.
- R060 (Suspicious Docker Activity) no longer fires on `privileged: false`.
- `pam_faillock` lines logged by sshd are now classified as `ACCOUNT_LOCKED`
  (previously a detection gap).
- Docker daemon timestamps with nanosecond precision failed to parse on
  Python 3.10.

### Known gaps

- R041/R042 cannot tell a legitimate `authorized_keys` edit from an attack
  because they match on the text.
- R031 and R050 score only "medium" risk.
- The benchmark is synthetic; passing it means "no regression", not real-world
  accuracy.
- The systemd units and the example UFW adapter have not been run on a live
  host. See [SECURITY.md](SECURITY.md) for the full list of known limitations.
